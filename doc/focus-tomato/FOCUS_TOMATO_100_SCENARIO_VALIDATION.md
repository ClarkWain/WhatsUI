# FocusTomato 100 个使用场景模拟验证

- 验证日期：2026-07-31
- 设计文件：[FocusTomato Figma](https://www.figma.com/design/H07PsWcER65ZVlsBBsZGlu?node-id=53-195)
- 验证对象：SPEC-01～SPEC-12、R-01～R-22 恢复/边界状态、跨页面入口/退出规则、计时状态机与数据处理规格
- 验证方式：基于当前 Figma 界面和产品规格进行桌面推演，不代表可运行程序、系统 API 或数据库已经完成实机测试
- 当前版本：v2。SC-01～SC-50 保留首次验证记录；“修复后复验”是当前设计层结论，并覆盖首次结论。

## 1. 判定标准

| 结论 | 定义 |
|---|---|
| 通过 | 当前 UI、交互规则和数据处理可以完整闭环，没有明显缺口 |
| 基本通过 | 主流程成立，但缺少提示、动效、快捷键说明或次要状态 |
| 存在风险 | 产品规则已有部分定义，但当前 UI 缺少关键状态、确认弹窗、错误态或入口 |
| 阻断 | 用户无法完成任务，或可能造成计时/数据错误、无法退出、无法恢复、无障碍不可用 |

问题等级使用 P0～P3：

- P0：发布阻断、数据一致性或关键可用性问题。
- P1：高频流程明显受损，应在开发主流程时完成。
- P2：低频异常或体验问题，应在 Beta 前完成。
- P3：体验优化。

## 3. SC-01～SC-50 首次验证记录（修复前）

### SC-01｜首次启动，没有任何任务

- 前置条件：全新安装；Task 表为空；无活动会话。
- 操作路径：启动应用 → SPEC-12 任务空状态。
- 预期结果：说明为什么页面为空；提供“新建任务”“导入任务”“直接专注”三条路径；关闭窗口可以正常退出。
- 数据验证：空态只由 `status=active` 的任务数量判断，不创建任何默认任务或会话。
- 当前验证：空态界面、三个行动方向及自由专注的数据规则均已定义。
- 结论：**通过**。

### SC-02｜创建第一个任务

- 前置条件：处于 SPEC-12；无活动会话。
- 操作步骤：点击“新建首个任务” → 输入标题和预计番茄数 → 保存。
- 预期结果：校验标题 1～80 字、预计番茄 1～99；保存成功后进入 SPEC-03 并选中新任务；失败时保留输入。
- 数据验证：单事务插入 Task，分配 `sortOrder`，写入 UTC 时间。
- 当前问题：规格写明“内联表单”，但当前空态设计稿没有展开态、输入框、校验文案、保存中和失败状态。
- 结论：**存在风险（P1）**。
- 建议：补充“新建任务表单”的默认、输入、校验失败、保存中、保存失败五个状态。

### SC-03｜从 CSV 导入一组任务

- 前置条件：处于 SPEC-12；准备包含标题和预计番茄数的 CSV。
- 操作步骤：点击“导入任务” → 选择文件 → 查看解析预览 → 勾选有效行 → 确认导入。
- 预期结果：展示有效行、错误行、重复标题和最终导入数量；确认后单事务写入；成功进入 SPEC-03。
- 数据验证：解析数据只能暂存在内存；确认后批量插入；失败必须全部回滚。
- 当前问题：当前 UI 只有“导入”入口描述，没有文件选择后的预览、列映射、错误行、重复处理和确认界面，流程无法实际完成。
- 结论：**阻断（P0）**。
- 建议：新增“导入预览/结果”页面或模态框；若 v1 不做导入，应从空态移除该入口，避免虚假能力。

### SC-04｜创建重名任务

- 前置条件：已有“完成产品设计稿”；用户再次创建同名任务。
- 操作步骤：新建任务 → 输入相同标题 → 保存。
- 预期结果：允许创建，但明确提示存在同名任务，并让用户确认或修改。
- 数据验证：标题不是唯一键；每个任务使用独立 UUID。
- 当前问题：规则允许重复并提示，但没有重复提示的 UI 状态和确认方式。
- 结论：**存在风险（P2）**。
- 建议：在输入框下展示非阻断警告，并提供“仍然创建”与“查看已有任务”。

### SC-05｜恢复已归档任务

- 前置条件：没有 active 任务，但存在 archived 任务。
- 操作步骤：进入 SPEC-12 → 点击“已归档任务” → 选择任务 → 恢复。
- 预期结果：恢复后任务回到 SPEC-03，历史 FocusSession 仍然保留。
- 数据验证：只更新 Task.status 和 updatedAt，不修改历史会话。
- 当前问题：空态规格包含归档入口，但当前设计稿没有归档列表、恢复操作及恢复后的排序规则。
- 结论：**存在风险（P1）**。
- 建议：补充“归档任务列表”模态框，或在任务页增加可切换的“已归档”筛选。

### SC-06｜筛选结果为空，但任务并不为空

- 前置条件：全部任务均为 done；当前筛选为“进行中”。
- 操作步骤：SPEC-03 切换到“进行中”。
- 预期结果：显示筛选空态“没有进行中的任务”，同时允许切回全部；不能错误进入首次使用的 SPEC-12。
- 数据验证：页面空态应区分 `filteredCount=0` 与 `activeTaskTotal=0`。
- 当前问题：规格已经区分两种空态，但仅设计了完整的任务空状态，没有设计筛选空结果。
- 结论：**存在风险（P1）**。
- 建议：在 SPEC-03 内增加轻量筛选空态，不发生页面跳转。

### SC-07｜拖拽调整任务顺序

- 前置条件：存在至少三个 active 任务。
- 操作步骤：拖拽第三个任务到第一位 → 关闭并重开应用。
- 预期结果：拖拽期间有落点反馈；保存后顺序稳定；键盘用户有替代操作。
- 数据验证：使用稀疏 `sortOrder`；间距耗尽时批量重排。
- 当前问题：任务行没有拖拽手柄、悬停反馈、落点状态和键盘“上移/下移”菜单。
- 结论：**存在风险（P1）**。
- 建议：增加拖拽手柄，并在更多菜单提供“上移、下移、置顶”。

### SC-08｜计时进行中查看任务列表

- 前置条件：SPEC-01 正在计时。
- 操作步骤：通过主导航或展开主窗进入 SPEC-03。
- 预期结果：顶部显示当前活动会话横幅；点击横幅返回计时；不能直接启动另一个任务。
- 数据验证：只读取唯一 `activeSessionId`，不得创建第二个会话。
- 当前问题：工程规格定义了活动会话横幅，但现有任务列表设计稿没有该横幅及冲突提示状态。
- 结论：**存在风险（P1）**。
- 建议：补充 running、paused、break 三种横幅文案和“返回计时”主操作。

### SC-09｜从任务列表启动一次普通专注

- 前置条件：有 active 任务；没有活动会话。
- 操作步骤：选择任务 → Enter 或双击 → SPEC-09 → 点击主播放按钮。
- 预期结果：展示任务、时长、声音和休息策略；创建会话成功后进入 SPEC-01。
- 数据验证：单事务创建 FocusSession 和 TimerSnapshot；配置复制为会话快照。
- 当前验证：入口、设置页、图标主按钮、事务和目标页面均已定义。
- 结论：**通过**。

### SC-10｜使用自定义 50 分钟专注

- 前置条件：SPEC-09；没有活动会话。
- 操作步骤：选择自定义时长 → 输入 50 → 确认 → 开始。
- 预期结果：摘要显示 50 分钟；FocusSession.plannedDurationMs 固化为 50 分钟；全局默认值不被修改。
- 数据验证：校验范围 1～180；override 只写 SessionConfig。
- 当前问题：规则完整，但当前设置页中的自定义输入、单位、错误提示和是否影响默认值不够直观。
- 结论：**基本通过（P3）**。
- 建议：在自定义项旁标注“仅本次”，并显示分钟单位。

### SC-11｜连续双击“开始专注”

- 前置条件：SPEC-09 配置有效；数据库写入有短暂延迟。
- 操作步骤：快速双击主播放按钮，或同时按 Ctrl+Enter。
- 预期结果：按钮立即进入 loading/disabled；只创建一个会话；最终只进入一次 SPEC-01。
- 数据验证：使用 pendingRequestId 和“唯一 active session”约束去重。
- 当前问题：数据去重规则存在，但主按钮没有设计 loading、disabled 和失败后的恢复状态。
- 结论：**存在风险（P1）**。
- 建议：增加 300ms 以上可见的提交状态，并在失败后恢复可点击。

### SC-12｜已有活动会话时再次进入设置页

- 前置条件：TimerStore 已有 running focus；用户通过快速入口再次进入 SPEC-09。
- 操作步骤：点击托盘“快速专注”或从其他任务进入设置。
- 预期结果：不展示可创建的新会话配置，改为“已有专注进行中”和“返回当前计时”。
- 数据验证：绝不能覆盖 activeSessionId。
- 当前问题：规格已规定冲突状态，但没有对应的 SPEC-09 冲突界面。
- 结论：**存在风险（P1）**。
- 建议：补充设置页的 active-session guard 状态，主按钮替换为“返回计时”。

### SC-13｜暂停并继续专注

- 前置条件：SPEC-01 running。
- 操作步骤：点击 68px 主按钮暂停 → 等待 → 再次点击继续。
- 预期结果：按钮图标在暂停/播放之间切换；暂停期间时间不减少；继续从正确剩余时间开始。
- 数据验证：暂停写 remainingMs、清 targetEndAt；继续写 `targetEndAt=now+remainingMs`。
- 当前验证：按钮主次、状态切换和数据算法均已明确。
- 结论：**通过**。

### SC-14｜使用键盘 Space 控制计时

- 前置条件：焦点不在文本输入框；SPEC-01 running 或 paused。
- 操作步骤：按 Space 暂停/继续；使用 Tab 查看焦点顺序。
- 预期结果：与点击主按钮一致；不会触发页面滚动；焦点可见。
- 数据验证：复用同一个 TimerStore.toggle 命令。
- 当前问题：快捷键规则明确，但界面没有快捷键提示，焦点环样式也未单独展示。
- 结论：**基本通过（P3）**。
- 建议：首次使用时显示一次快捷键提示，并在组件库补充 focus-visible 状态。

### SC-15｜已专注 10 分钟后点击重置

- 前置条件：SPEC-01 已消耗时间大于 0。
- 操作步骤：点击重置图标 → 查看确认 → 确认。
- 预期结果：明确说明“已专注进度将清零但不会计为完成”；确认后恢复 plannedDurationMs。
- 数据验证：重置更新当前 session 的 remainingMs，不增加统计，不生成新会话。
- 当前问题：规则要求确认，但设计稿没有重置确认弹窗、取消操作和是否记录已消耗时长的说明。
- 结论：**存在风险（P1）**。
- 建议：补充统一的会话破坏性操作确认组件。

### SC-16｜主动提前结束专注

- 前置条件：SPEC-01 running 或 paused。
- 操作步骤：点击结束 → 二次确认 → 返回任务列表。
- 预期结果：说明本次不会计入完成番茄；取消后保持原状态；确认后进入 SPEC-03。
- 数据验证：写 status=aborted、清 TimerSnapshot；不得增加任务和统计数据。
- 当前问题：结束按钮存在，但缺少确认弹窗和“是否计入统计”的明确反馈。
- 结论：**存在风险（P1）**。
- 建议：确认弹窗显示已专注时长，并明确“不计入番茄和专注时长”。

### SC-17｜专注期间任务被归档

- 前置条件：focus 会话正在运行；关联任务在另一入口被归档。
- 操作步骤：返回计时页 → 完成会话。
- 预期结果：计时页仍显示启动时的任务标题；会话可以正常完成；完成页隐藏“继续原任务”。
- 数据验证：使用 `titleSnapshot`；历史 session 保留 taskId；任务缓存只按规则更新。
- 当前验证：任务快照、归档兼容和完成页退出规则均已覆盖。
- 结论：**通过**。

### SC-18｜专注时关闭主窗口

- 前置条件：SPEC-01 running；minimizeToTray=true。
- 操作步骤：点击窗口关闭按钮 → 再从托盘打开。
- 预期结果：主窗隐藏，计时继续；托盘/迷你窗展示同一剩余时间；再次打开返回 SPEC-01。
- 数据验证：只写 UIState 和快照，不改变会话状态。
- 当前问题：规则完整，迷你窗也已设计；但 Windows/macOS/Linux 的首次关闭行为提示尚未设计。
- 结论：**基本通过（P2）**。
- 建议：首次关闭时显示一次“应用仍在托盘运行”，并提供“不再提示”。

### SC-19｜记录一次中断并继续

- 前置条件：SPEC-01 running。
- 操作步骤：点击“记录中断” → 选择“消息” → 输入备注 → “记录并继续”。
- 预期结果：进入中断页前暂停；提交成功后恢复原剩余时间并返回 SPEC-01。
- 数据验证：事务插入 Interruption，然后恢复 targetEndAt；备注只保存在本地。
- 当前验证：专用中断界面、原因、备注、继续路径和事务顺序均已定义。
- 结论：**通过**。

### SC-20｜打开中断页面后取消

- 前置条件：由 SPEC-01 进入 SPEC-10；未提交。
- 操作步骤：按 Esc 或点击返回。
- 预期结果：不创建 Interruption；返回 paused 的 SPEC-01，由用户手动继续。
- 数据验证：打开表单不落库；只保留 paused session。
- 当前验证：入口和退出规则明确，不会产生假中断数据。
- 结论：**通过**。

### SC-21｜记录中断后结束本次专注

- 前置条件：SPEC-10 已选择原因。
- 操作步骤：点击“结束本次专注” → 二次确认。
- 预期结果：记录中断、终止会话、清快照、进入任务列表；不得计为完成。
- 数据验证：插入 Interruption 与写 aborted 必须在同一事务中。
- 当前问题：结束路径有定义，但缺少中断页专用确认弹窗及事务失败状态。
- 结论：**存在风险（P1）**。
- 建议：弹窗明确“中断记录会保留，本次番茄不会完成”。

### SC-22｜填写中断备注时应用崩溃

- 前置条件：SPEC-10；会话已 paused；备注未提交。
- 操作步骤：模拟进程崩溃 → 重新启动。
- 预期结果：恢复 paused 会话；未提交的中断不写入；提示用户继续计时或重新记录。
- 数据验证：TimerSnapshot 可恢复会话；中断草稿默认不持久化。
- 当前问题：数据结果明确，但恢复后的选择界面、未保存备注提示和恢复入口没有独立设计。
- 结论：**存在风险（P2）**。
- 建议：增加“检测到暂停中的专注”恢复条，避免用户不知道为什么计时停住。

### SC-23｜系统睡眠后在计时结束前唤醒

- 前置条件：剩余 15 分钟；系统睡眠 5 分钟。
- 操作步骤：系统 suspend → resume。
- 预期结果：唤醒后剩余约 10 分钟；不出现重复计时器；页面状态不跳变。
- 数据验证：使用 `max(0,targetEndAt-now)`，不依赖逐秒持久化。
- 当前验证：算法和 suspend 保存时机已经明确。
- 结论：**通过**。

### SC-24｜系统睡眠跨过计时结束时间

- 前置条件：剩余 2 分钟；系统睡眠 10 分钟。
- 操作步骤：唤醒应用。
- 预期结果：只执行一次完成结算并进入 SPEC-07；今日番茄只增加 1。
- 数据验证：以 session.id 为幂等键；重复唤醒和通知事件返回同一 CompletionResult。
- 当前验证：完成事务和幂等逻辑完整。
- 结论：**通过**。

### SC-25｜用户手动把系统时间调回 30 分钟

- 前置条件：SPEC-01 running；已运行一段时间。
- 操作步骤：修改系统时间 → 返回应用。
- 预期结果：不会无故增加 30 分钟；提示检测到系统时间变化，并给出继续、按实际时间校正或结束。
- 数据验证：当前运行段结合单调时钟校验，不能只信任 wall clock。
- 当前问题：规格提到单调时钟和提示，但没有时间异常提示 UI、默认选择及跨平台实现边界。
- 结论：**存在风险（P1）**。
- 建议：定义阈值（如偏差超过 2 分钟）及明确的恢复弹窗。

### SC-26｜计时完成时数据库写入失败

- 前置条件：SPEC-01 到达 00:00；SQLite 暂时不可写或磁盘已满。
- 操作步骤：触发完成事务 → 模拟事务失败。
- 预期结果：不能展示“完成成功”或增加番茄；保留可恢复快照；显示明确错误和“重试保存”。
- 数据验证：FocusSession、Task 缓存、TimerSnapshot 和 outbox 必须原子提交；失败全部回滚。

- 结论：**阻断（P0）**。
- 建议：新增 `completion_pending` UI 状态，提供重试、导出诊断和安全退出；重试仍使用 session.id 幂等。

## 7. 推荐开发门禁

### UI/交互门禁

- 每个可破坏当前进度的操作必须有确认或撤销。
- 每个异步提交必须具备 loading、disabled、成功、失败和重试。
- 每个页面必须实现当前规格中的进入守卫和退出守卫。
- 有 activeSession 时，任何页面都必须能返回当前会话。

### 数据门禁

- 数据库层保证任意时刻最多一个 active session。
- 完成结算按 session.id 幂等，并在单事务内更新会话、任务缓存、快照和 outbox。
- 统计只从原始 completed focus sessions 生成，所有缓存可重建。
- 休眠、重启、重复通知和重复 IPC 命令不得造成重复结算。

### 测试门禁

- 以上 50 条场景至少形成 50 条可追踪测试用例。
- SC-11、SC-24、SC-26、SC-35、SC-37 必须做自动化或故障注入测试。

- 操作：在任务列表修改关联任务名，再返回计时。
- 预期：本次会话继续显示启动时 titleSnapshot；下一次使用新标题。
- 数据：不回写当前 session snapshot。
- 结论：**通过**。

### SC-93｜周期中修改 longBreakEvery

- 前置条件：本周期已完成 3 个番茄；设置从 4 改为 6。
- 操作：完成第 4 个番茄。
- 预期：当前运行会话不变；完成时使用最新设置决定下一休息，第 4 个后短休息。
- 数据：longBreakEvery 不写入 focus session，休息决策在完成事务后读取；已开始的 break 不变。
- 结论：**通过**；规则在本报告中锁定。

### SC-94｜自然完成与用户点击“结束”同时发生

- 前置条件：剩余不到一秒。
- 操作：计时回调与结束确认同时提交。
- 预期：只有一个终态；若 completed 先提交则结束请求显示“已完成”，不得改成 aborted。
- 数据：终态 compare-and-set，completed/aborted 不可互相覆盖。
- 结论：**通过**。

### SC-95｜完成事务提交时系统关机

- 前置条件：completion_pending。
- 操作：操作系统强制结束进程。
- 预期：重启后根据事务结果恢复：已提交则显示完成结果，未提交则幂等重试。
- 数据：SQLite 原子事务 + 保留 completion intent。
- 结论：**通过**；R-07 和完成幂等规则闭环。

### SC-96｜未来云同步重复发送 outbox

- 前置条件：同一完成事件因网络重试发送两次。
- 操作：服务端/另一设备处理重复事件。
- 预期：只生成一个远端会话和一次任务增量。
- 数据：outbox eventId=session.id+eventType；服务端幂等。
- 结论：**通过**；当前本地数据模型已经预留。

### SC-97｜导出脱敏诊断包

- 前置条件：R-07/R-24 错误。
- 操作：打开 R-27 → 预览字段 → 保存诊断包。
- 预期：用户知道保存位置和内容；不包含任务标题、备注、文件路径。
- 数据：只输出版本、错误码、schema、状态计数。
- 结论：**通过**。

### SC-98｜活动会话中备份数据库

- 前置条件：focus running。
- 操作：从 R-24/R-27 保存数据库备份。
- 预期：备份可打开且内部一致；计时不明显中断；备份说明包含时间。
- 数据：使用 SQLite online backup/snapshot API，不直接复制正在写入的文件。
- 结论：**基本通过**；界面和安全边界明确，需数据库集成测试。

### SC-99｜系统区域格式使用逗号分隔

- 前置条件：某些地区数字/CSV 分隔符不同。
- 操作：设置分钟、导入 CSV。
- 预期：分钟仍只接受整数；导入允许选择逗号、分号或自动检测。
- 数据：存储使用数值，不保存本地化字符串。
- 结论：**基本通过**；R-14 可承载编码/格式提示，解析器需区域化测试。

### SC-100｜连续运行 30 天

- 前置条件：频繁开始/结束、打开统计、切换声音，应用长期不退出。
- 操作：进行 soak test。
- 预期：内存、句柄、定时器、音频实例和数据库连接不持续增长；托盘保持响应。
- 数据：完成后释放 timer/audio/notification 资源；缓存有上限。
- 结论：**基本通过**；R-25 定义性能方向，必须进行真实 30 天加速/长稳测试。
