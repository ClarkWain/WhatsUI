## 本轮已修复的工程问题

1. 完成结算持久化失败后，`CompletionPending` 会在后续 tick 或重启后幂等重试，不再永久停在 00:00。
2. 应用重启会根据活动会话恢复专注或休息页，并恢复关联任务上下文。
3. `autoStartBreak=false` 会原子创建暂停的休息会话；长休息按原始会话历史重建周期。
4. 完成检查点建立后，结束/跳过命令不能覆盖自然完成终态。
5. 相同 ID 但参数不同的任务或会话命令返回冲突，不再伪装成幂等成功。
6. 活动会话关联任务禁止删除，但允许编辑；运行会话继续使用不可变 `titleSnapshot` 并可正常结算。
7. 系统时钟前后跳变会使用单调时钟计算实际经过时间并安全暂停，不会凭空增加专注时间。
8. 任务筛选、筛选空态、编辑、软删除、已删除筛选、恢复、完成/恢复任务和预计番茄数 1～99 已形成真实交互闭环。
9. 自由专注可以从空任务页开始、完成、计入统计并继续下一轮。
10. 重置、提前结束和跳过休息改为确认后执行；取消不会写业务数据。
11. “今日”统计改为按本地日历日的 `[from, to)` 区间计算，兼容 23/25 小时的 DST 日期。
12. 长/短休息共用同一状态机，但 UI 会根据真实会话类型显示正确标题、时长和说明。
13. 任务页作为稳定根页面；准备、专注、完成和休息可安全返回，返回不写数据，收起后的计时仍会更新和结算。
14. 任务可设置 1～180 分钟单轮时长，并选择跟随全局、静音或具体声音；开始会话时把有效时长和声音 ID 冻结为不可变快照。旧任务文件安全迁移为跟随全局。

## 发布判断

当前实现已经能够可靠闭环“任务/自由专注 → 暂停/继续/重置/结束 → 完成结算 → 长短休息 → 返回任务”，任务编辑、软删除和恢复也已闭环，但还不是 100 场景意义上的完整桌面产品。白噪音、导入、设置页、周统计、迁移和长稳测试仍应作为后续独立里程碑；在这些能力实现前，不应把设计报告中的 100 个“通过”作为发布依据。
